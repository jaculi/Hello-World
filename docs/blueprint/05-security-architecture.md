> 状态：**v0.1**（2026-09-05）

> 下游消费者：[BP-04 技术架构](./04-technology-architecture.md)（选型须满足本文约束）、[BP-06 集成与生态](./06-integration-and-ecosystem.md)（SPI 权限模型/开放 API 认证）、[BP-07 部署与运营](./07-deployment-and-operations.md)（SecOps 落地）

## 1. 目的与范围

本文定义 JSL 平台的安全架构，覆盖六个层面：

1. **身份与访问管理（IAM）**：人、服务、插件、API 应用、设备的统一身份与认证；
2. **授权模型**：统一 RBAC（+属性约束）与权限决策流程；
3. **租户隔离安全**：T1–T3 隔离的强制执行与越界防护；
4. **数据安全**：分类分级、加密、脱敏、留存销毁、隐私合规；
5. **插件与生态安全**：插件准入、沙箱、权限声明、供应链；
6. **AI 安全与审计合规**：闸门安全、模型风险、审计模型、合规映射。

硬约束（继承自 ADR-0001/0002 与 BP-02/03）：

- **五类主体（人/服务/插件/API 应用/设备）统一走 IAM，不另建权限体系**；
- **默认拒绝（deny-by-default）**：一切未经显式授予的能力不可用；
- **纵深防御**：网关粗校验 + BC 细校验 + 数据库 RLS（BP-03 §3.2），任何单点失效不导致越界；
- **AI ≠ 授权**：AI 的建议/决策执行时同样过 RBAC；闸门 fail-closed；
- **审计只追加不可篡改**，AI 裁决与插件行为必须可追溯。

## 2. 安全架构总览（纵深防御视图）

```
第0层 边界安全     WAF/DDoS/限流（网关）│ 网络分区（公网区/接入区/核心区/数据区）
第1层 身份安全     统一 IAM：五类主体认证 │ MFA/step-up │ 设备一机一密
第2层 授权安全     RBAC+ABAC 决策 │ 网关粗校验 → BC 细校验 → 行级/字段级
第3层 租户隔离     T1/T2/T3 强制收敛（BP-03 §3.2）│ 越界对账
第4层 插件沙箱     进程/容器隔离 │ 能力声明 deny-by-default │ 资源配额
第5层 数据安全     分类分级 │ 加密(传输/静态) │ 脱敏 │ 留存销毁
第6层 AI 安全      五因子闸门 fail-closed │ 模型风险防护 │ AI 审计
第7层 审计合规     统一审计模型 │ 不可篡改留痕 │ 合规映射(等保/GDPR/行业)
```

## 3. 身份与访问管理（IAM，BC-P2）

### 3.1 五类主体与认证方式

| 主体 | 认证方式 | 凭证形态 | 说明 |
|---|---|---|---|
| 人（用户） | 密码+MFA / OIDC SSO（企业 IdP 联合登录） | 短期会话 Token（JWT） | 支持租户自建 IdP 联合（企业运营客户常态） |
| 服务账号（BC 间调用） | 工作负载身份 + mTLS | 短期自动轮换凭证 | 内部 BC 互信，禁止长期静态密钥 |
| 插件实例 | 平台签发的插件身份（运行时注入） | 受限 Token（绑定插件实例+租户范围） | 沙箱内自动携带，应用不可读取 |
| 第三方应用（开放 API） | OAuth2.0（Client Credentials / Authorization Code） | API Key+Secret 换短期 Token | 授权码模式用于"代表用户"场景，须用户同意页 |
| 设备 | X.509 证书 / 一机一密 Token | 设备凭证（可吊销） | 经 BC-I1 接入，证书轮换策略按行业 |

要点：

- 所有 Token 最小生命周期 + 刷新机制；凭证全生命周期（签发/轮换/吊销）入审计；
- 高风险操作触发 **step-up 认证**（再次验证/MFA），如警备处置确认、医疗数据批量导出、租户管理员变更。

### 3.2 账号生命周期

- 用户：租户内邀请/同步（企业 IdP 目录同步）→ 启用/停用 → 离职自动回收（联合登录随 IdP 会话失效）；
- API 应用：开发者门户申请 → 平台审核（BP-06）→ 吊销机制；
- 设备：注册（审批制或预共享）→ 挂失吊销 → 重新注册留痕。

## 4. 授权模型（统一 RBAC + 属性约束）

### 4.1 模型定义

```
权限 Permission = 资源类型 × 动作 × 约束(可选)
角色 Role（有 scope）：PLATFORM / TENANT_ADMIN / ORG / SITE / 行业模板预置 / 租户自定义
授权 Grant = (主体, 角色, 资源范围 Scope)
资源范围 Scope = tenant ⊃ org ⊃ site（层级继承）
数据权限 = 行级(站点/组织范围) + 字段级(敏感字段掩码)
```

### 4.2 决策流程（每个请求三道闸）

```
请求 → ① 网关：认证 + 粗粒度授权（路由级权限/套餐配额/限流）
     → ② BC：细粒度授权（BC-P2 决策：功能权限 + 数据权限）
     → ③ 数据层：RLS/租户路由（BP-03）兜底
风险属性（ABAC 补充）：操作风险等级 → 触发 step-up / 二人复核 / 审批流
```

- **功能权限**：能否调用某 API/操作某资源类型；
- **数据权限**：能看/操作**哪些范围**的数据（行级：站点/组织；字段级：敏感字段脱敏，如生命体征详情、人脸抓拍原图）；
- **职责分离（SoD）**：关键行业内置约束，如医疗数据访问与审计查看角色分离；警备处置确认人与工单执行人不得同一人（可按租户配置）。

### 4.3 行业模板的 RBAC 装配

- 行业模块包（BP-02 §6.1）携带 `rbac/` 预置角色与权限集（如"护士站查看者""警备值机员""巡更执行人"），安装时并入租户角色目录；
- 预置角色可被租户改名/复制，**不可越出模板声明的权限上限**（插件权限天花板原则，见 §7.3）。

## 5. 租户隔离安全

在 BP-03 §3 的 T1/T2/T3 与五层收敛机制之上，安全侧强化：

| 威胁 | 对策 |
|---|---|
| 应用层租户过滤遗漏 | RLS 兜底（T3）；Schema 权限（T2）；独立库（T1）——应用漏洞不直接导致跨租户 |
| 越权 API 调用 | 网关校验 Token 租户声明与路由租户一致；BC 内二次校验资源归属 |
| 缓存/队列串租户 | 所有缓存键、消息分区键强制携带租户前缀；消费端校验信封 `tenant_id` 与处理上下文一致 |
| 对象存储越权 | 桶按租户前缀 + STS 临时凭证下发（限定前缀与时长），禁止长期 AK 直连 |
| 插件越界 | 见 §7：插件 Token 绑定租户范围，宿主 BC 调用时校验订阅+配额+权限 |
| 越界检测 | BP-03 §3.2 定期对账 + 实时异常引用告警 → P5 审计 → 安全事件响应（§10） |

## 6. 数据安全

### 6.1 分类分级与控制矩阵

在 BP-03 §2.1 数据分类（D1–D8）之上叠加敏感度分级：

| 级别 | 定义 | 示例 | 控制基线 |
|---|---|---|---|
| S1 公开/内部 | 平台配置、非敏感运营数据 | 菜单、公告 | 访问控制、审计 |
| S2 业务 | 一般业务数据 | 工单、设备档案、能耗数据 | + 租户隔离、字段级权限 |
| S3 敏感 | 个人相关、业务关键 | 人员档案、警情记录、位置轨迹 | + 加密(静态)、脱敏展示、导出审批 |
| S4 高敏 | 受监管数据 | 医疗健康体征、人脸/生物特征、未成年人数据、警备布防细节 | + 专有隔离(T1/T2)、字段加密、step-up 访问、留存合规、默认字段级掩码 |

### 6.2 加密与密钥

- **传输**：全链路 TLS（外部 TLS1.2+/内部 mTLS）；IoT 接入按协议启用 DTLS/TLS；
- **静态**：S3/S4 级字段级加密（应用层加密，密文入库）；存储与对象存储盘加密为基线；
- **密钥管理**：平台根密钥 + 租户级数据密钥（信封加密）；T1 客户可选自带密钥（BYOK）；密钥轮换与吊销留痕。

### 6.3 脱敏与匿名化

- 展示脱敏按字段级数据权限自动执行（§4.2）；导出必审批 + 水印（操作者身份嵌入）；
- 进入 AI 数据管道（BP-03 §8.2）前完成匿名化/假名化；生物特征原始数据**默认不出采集域**，只输出特征向量/分析结果（医疗、警备视频人脸严格按此）；
- 开发/测试环境禁止使用 S3/S4 真实数据，用合成数据。

### 6.4 留存与销毁

| 数据 | 默认留存 | 说明 |
|---|---|---|
| 审计与 AI 裁决记录 | ≥3 年（警备/医疗按行业要求更长） | 不可篡改（§9.2） |
| 时序遥测 | 按 BP-03 §6（TTL+降采样） | 租户可配（不越套餐下限） |
| 视频录像 | 按套餐（如 30/90 天），警情关联片段单独归档（证据链） | S1 生产者 |
| 租户注销 | 数据冻结期（默认 30 天）→ 全级联删除 + 删除证明 | 满足数据主体删除权 |

## 7. 插件与生态安全

### 7.1 插件准入（上架前）

1. **来源审核**：开发者实名/企业认证（BP-06 流程）；
2. **供应链安全**：包签名验证（平台公钥）、依赖与镜像漏洞扫描、SBOM 提交；
3. **权限评审**：manifest 权限声明与功能相符性人工评审；AI 能力插件必须携带场景与风险元数据（ADR-0002），否则拒绝上架。

### 7.2 沙箱运行时（BC-E1 执行）

| 机制 | 要求 |
|---|---|
| 隔离边界 | 插件运行于独立进程/容器；无宿主文件系统、无直接网络、无共享内存 |
| 交互通道 | 仅经 SPI RPC 与事件通道（宿主代理），全部调用可拦截、可审计 |
| 系统资源 | CPU/内存/带宽/线程配额（cgroup 级），超限熔断 |
| 调用频率 | SPI 调用限流（每插件实例 per 租户） |
| 故障隔离 | 插件崩溃不影响宿主 BC；自动重启 + 连续失败熔断下线并告警 |

### 7.3 插件权限模型（能力声明 + 天花板）

- manifest 声明：所需扩展点（BP-02 §6.2 SPI）、**数据范围（tenant/org/site + 字段清单）**、资源配额、外联地址白名单；
- **deny-by-default**：未声明能力一律拒绝；
- **权限天花板**：插件运行时获得的权限 ≤ 上架评审通过的声明 ≤ 行业模板给租户配置的上限（三级取交）；
- **安装知情**：租户安装插件时展示权限清单（同移动 App 权限模型），敏感权限（读取 S4 数据、外发数据）单独标红确认；
- 外联管控：插件对外网络仅允许白名单地址，且经出口代理审计流量。

### 7.4 运行期监控

- 插件行为画像（调用量/数据访问量/错误率）异常检测 → 可疑插件一键停用（租户级/平台级）；
- 插件数据访问全部落入审计（§9.1），带 `plugin_id + version`。

## 8. AI 安全（承接 ADR-0002）

| 风险 | 对策 |
|---|---|
| 闸门自身故障/被绕过 | fail-closed（闸门不可用即拒绝自动执行，降级 L3）；闸门调用为 BC-A1 强制路径，BC-A1 拒绝无 `GateDecision` 引用的推理；闸门高可用部署（BP-04） |
| AI 决策越权执行 | AI ≠ 授权：L1 自动执行的动作使用**专用系统角色**，其权限仅覆盖该场景声明的资源与动作 |
| 租户数据进模型 | 租户数据默认不用于公共模型训练；租户专属模型/微调数据存于租户隔离单元（BP-03 T 级一致）；跨租户共享模型只允许匿名化特征 |
| Prompt 注入 / 内容风险 | LLM 输入隔离（用户内容与系统指令分层）、输出过滤、工具调用最小权限、外部内容（网页/文档）视为不可信 |
| 模型供应链 | 模型/算法包经 AI Capability SPI 注册时签名校验、来源审核；模型版本可回滚（BC-A1 资产管理） |
| 模型输出可追溯 | 每次推理记录：输入特征引用/模型版本/输出/置信度/闸门裁决 ID，入审计（§9.1） |

## 9. 审计与合规

### 9.1 统一审计模型（BC-P5）

所有审计事件统一结构：

```
who(主体: 用户/服务/插件/设备/第三方应用) │ when(UTC)
where(tenant/org/site/ip/trace) │ what(动作 + 资源)
result(成功/拒绝) │ context(插件id+版本 / AI裁决id / step-up证明)
```

- 覆盖：认证事件、授权拒绝、数据导出、S3/S4 数据访问、插件调用、AI 裁决与执行、配置变更（RBAC/策略/插件装卸）、越界对账结果；
- 权限被拒事件同样留痕（入侵排查与权限调优双用途）。

### 9.2 不可篡改与可追溯

- 审计流**只追加**：哈希链（前后事件摘要链接）+ WORM 存储/独立权限账号；
- AI 裁决审计关联链：闸门决策 ID → 因子输入快照 → 推理记录 → 执行记录（完整证据链，承接 ADR-0002）；
- 警备证据链（录像+警情+处置）与医疗操作记录按证据完整性要求管理（哈希校验+时间戳）。

### 9.3 合规映射（基线声明，具体认证由运营侧执行）

| 域 | 要求 | 架构支撑 |
|---|---|---|
| 等保 2.0（三级基线） | 身份鉴别、访问控制、安全审计、数据完整性保密性 | §3–§6、§9 |
| GDPR 类隐私 | 数据主体权利（查询/更正/删除/可携带）、最小化 | §6.4 注销删除、§6.3 匿名化、字段级权限 |
| 医疗行业 | 数据本地化/专有部署、高敏控制、操作可追溯 | T1 专有云、S4 基线、§9.2 |
| 警备行业 | 证据链完整性、处置留痕、留存期限 | §9.2、§6.4 |
| 多区域部署 | 数据驻留（区域化存储与路由） | BP-07 区域化部署承接 |

## 10. 安全运营（SecOps，与 BP-07 衔接）

- **安全监控**：认证异常（暴破/异地）、越权尝试激增、插件行为异常、闸门拒绝率异常 → 安全告警（独立于业务告警通道）；
- **漏洞管理**：依赖/镜像/漏洞扫描进 CI；分级 SLA 修复（严重 72h 基线）；
- **事件响应**：分级预案（越租户事件=最高级：自动隔离租户会话与插件、保全证据、通知与复盘流程）；
- **密钥与证书轮换**、**渗透测试**（大版本前 + 年度）纳入运营日历（BP-07）。

## 12. 开放问题（后续决策）

1. 沙箱运行时技术选型（容器/gVisor 类强隔离/WASM）——BP-04 ADR，需权衡 AI 能力插件（GPU 推理）的隔离与性能。
2. 插件 manifest 权限字段的正式规范（与 SPI 接口一并）——BP-06 + 专项 ADR。
3. 行业 SoD 与 step-up 规则的默认矩阵（医疗/警备细则）——行业共创。
4. BYOK 与跨区域密钥体系（多区域部署时）——BP-07/BP-04 联合决策。
5. 联合登录的企业 IdP 适配范围（Azure AD/Okta/国内主流）——按目标市场排期。
