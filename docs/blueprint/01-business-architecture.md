## 1. 目的与范围

本文定义 JSL 平台的业务架构三要素：

1. **行业域地图**：平台覆盖哪些行业，各行业接入什么、诉求是什么、风险特征如何；
2. **业务能力地图**：平台提供哪些能力，共性能力与行业差异如何分界；
3. **多租户运营模型**：租户层级、开通模式、订阅与计量。

本文回答"平台做什么生意、能力如何组织"；技术实现（服务拆分、数据模型、部署）交由 BP-02 及之后的蓝图。

## 2. 行业域地图

### 2.1 行业域总览

```
                         ┌─────────────────────┐
                         │   JSL 多租户 AIoT    │
                         │   智能运营平台        │
                         └──────────┬──────────┘
        ┌──────────┬──────────┬────┴─────┬──────────┬──────────┐
        │          │          │          │          │          │
   ┌────┴───┐ ┌────┴───┐ ┌────┴───┐ ┌────┴───┐ ┌────┴───┐ ┌────┴───┐
   │ 企业运营 │ │ 工业IoT │ │ 智慧楼宇│ │ 智能农业│ │ 智能医疗│ │ 远程警备│ ...
   └────────┘ └────────┘ └────────┘ └────────┘ └────────┘ └────────┘
        （每行业 = 行业模块插件 + 预置场景模板 + 预置 AI 能力）
```

### 2.2 行业域特征矩阵

| 行业域 | 典型场景 | 典型接入对象 | 核心诉求 | 典型风险等级（关联 ADR-0002 自动化分级） |
|---|---|---|---|---|
| **企业运营** | 办公管理、资产管理、能耗管理、流程审批 | 门禁、考勤、能耗表、办公设备、环境传感 | 降本增效、流程自动化、数据驱动运营 | 低—中（L1 为主） |
| **工业 IoT** | 产线监控、预测性维护、能耗与安监 | PLC、CNC、传感器、网关、工业相机 | 连续生产、质量稳定、安全合规 | 中—高（安监类须 L2/L3） |
| **智慧楼宇** | 楼控 BA、能耗、停车、安防、空间管理 | BA 系统、电梯、空调、照明、门禁、视频 | 舒适、节能、安全三位一体 | 低—中（L1/L2） |
| **智能农业** | 温室环控、水肥灌溉、养殖监控、产量分析 | 土壤/气象传感器、水肥机、环控设备、摄像头 | 产量与品质、资源节约、少人化 | 低—中（L1/L2） |
| **智能医疗** | 远程监护、医疗设备管理、院区环境 | 生命体征设备、医疗设备、环境传感、呼叫系统 | 患者安全、隐私合规、零差错 | **高（默认 L3，人决策）** |
| **远程警备** | 视频监控、入侵报警、联网报警运营、巡更 | 摄像头、报警主机、门磁、对讲、警灯警号 | 及时响应、零漏报、处置留痕 | **高（处置动作 L2/L3）** |
| **未来行业** | （扩展位） | — | — | — |

### 2.3 行业共性与差异的分界

- **共性（平台内核承载）**：租户/组织/权限、设备接入与管理、数据采集、告警与工单、AI 能力、通知、报表、计量计费、i18n。
- **差异（行业模块承载）**：行业业务对象（如医嘱、警情、温室配方）、行业流程（如报警处置 SOP、医疗监护规则）、行业合规（如医疗数据合规、警备运营资质）、行业预置 AI 场景包。

原则：**新行业接入 = 开发一个行业模块插件（含预置模板），不改平台内核**（ADR-0001）。

## 3. 业务能力地图

### 3.1 能力地图总览（L1）

```
┌───────────────────────────── 生态能力 ─────────────────────────────┐
│  开放 API │ 插件框架与市场 │ 开发者门户 │ 第三方应用                  │
├───────────────────────────── AI 横向能力层 ─────────────────────────┤
│  AI-Ready 数据加工 │ 模型/算法服务 │ AI Policy 五因子闸门             │
│  自动化执行编排(L1/L2/L3) │ 模型资产管理(注册/版本/监控)              │
├────────────────── Business 业务域 ──────────┬── 安全运营域 ─────────┤
│  主数据(空间/资产/人员/产品) │ 运营监控与报表 │  视频监控             │
│  工作流与工单 │ 巡检/维保/能源(可插件)        │  入侵报警与警情管理     │
│  业务规则 │ 协作与通知                       │  事件处置与应急联动     │
│                                             │  巡更巡检             │
├──────────────────────── IoT 设备域 ─────────┴───────────────────────┤
│  设备接入(多协议/网关/边缘) │ 设备管理(注册/影子/OTA/故障)            │
│  数据采集与时序存储 │ 规则引擎与联动 │ 告警管理                       │
├──────────────────────── 平台基座能力 ───────────────────────────────┤
│  租户与组织 │ 统一 IAM/RBAC │ i18n/本地化 │ 计量计费 │ 审计合规       │
└────────────────────────────────────────────────────────────────────┘
```

### 3.2 能力清单（L2）

#### 平台基座（Platform Base）

| 能力 | 说明 |
|---|---|
| 租户与组织管理 | 租户开通/冻结/注销、租户内组织架构、站点（Site）管理 |
| 统一 IAM / RBAC | 人、服务账号、插件、API Key 的认证与授权；角色/数据权限 |
| i18n 与本地化 | 多语言、多时区、多币种、区域格式 |
| 计量与计费 | 资源与用量计量、套餐订阅、账单 |
| 审计与合规 | 全链路操作审计、日志留存策略 |

#### IoT 设备域

| 能力 | 说明 |
|---|---|
| 设备接入 | 多协议接入（MQTT/Modbus/OPC-UA/HTTP…经协议插件扩展）、边缘网关、设备认证 |
| 设备管理 | 设备注册/影子（期望态 vs 上报态）、分组、OTA 升级、故障与生命周期 |
| 数据采集 | 时序数据上报、数据质量评估（供 AI 五因子中的"数据质量"裁决） |
| 规则引擎与联动 | 条件触发、场景联动、定时策略 |
| 告警管理 | 告警产生、分级、降噪（可由 AI 承担）、认领与恢复 |

#### Business 业务域

| 能力 | 说明 |
|---|---|
| 主数据管理 | 空间（楼宇/厂区/园区/地块）、资产、人员、产品的行业中性建模 |
| 工作流与工单 | 审批流、工单派发与闭环（告警 → 工单 → 处置 → 复盘的主干载体） |
| 运营监控与报表 | 驾驶舱、KPI、报表（多租户视角 + 租户内视角） |
| 巡检 / 维保 / 能源 | 计划巡检、维保策略、能耗分析——以业务功能插件形式按行业装配 |
| 业务规则 | 行业规则配置（规则引擎承载，AI 之外的低成本决策路径） |

#### 安全运营域

| 能力 | 说明 |
|---|---|
| 视频监控 | 通道接入、录像计划、取流分发（视频分析经 AI 能力层） |
| 入侵报警与警情管理 | 报警接入、警情分级、处置 SOP、联动（声光/对讲/复核） |
| 事件处置与应急联动 | 事件 → 处置流程 → 证据链留痕；跨系统联动编排 |
| 巡更巡检 | 巡更计划、点位打卡、漏检稽核 |

#### AI 横向能力层（所有域按需调用）

| 能力 | 说明 |
|---|---|
| AI-Ready 数据加工 | 特征抽取、样本标注、数据集管理（承接 ADR-0002 "能力普惠"） |
| 模型/算法服务 | 视觉识别、时序预测、异常检测、LLM 助手等；模型可插件接入 |
| AI Policy 闸门 | 五因子（业务价值/数据质量/风险/权限/成本）统一裁决（ADR-0002） |
| 自动化编排 | 按 L1/L2/L3 分级执行：自动闭环 / 建议+人工确认 / 仅洞察 |
| 模型资产管理 | 模型注册、版本、效果监控、下架 |

#### 生态能力（详见 BP-06）

| 能力 | 说明 |
|---|---|
| 开放 API（北向） | 设备数据、AI 服务、业务流程、告警事件的开放调用 |
| 插件框架（南向 SPI） | 协议/AI/行业/业务四类插件的接入契约与运行时 |
| 插件市场与开发者门户 | 上架、审核、订阅安装、分成结算 |

## 4. 多租户运营模型

### 4.1 租户层级模型

```
Platform（平台运营方）
 └── Tenant（租户 = 客户企业/运营主体）
      └── Organization（租户内组织：部门/子公司/项目组）
           └── Site（站点 = 物理/逻辑场地：工厂、楼宇、农场、院区、网点）
                ├── 设备、空间、资产、业务数据（归属站点）
                └── User（用户，经 IAM 授权进入）
```

要点：

- **站点（Site）是行业中性的核心概念**：工业的"厂区"、楼宇的"单体楼"、农业的"农场/地块"、医疗的"院区"、警备的"防护点位群"统一建模为 Site；行业模块在 Site 之上做行业化扩展。
- **数据归属到租户，物理挂载到站点**；跨租户数据严格隔离（隔离技术细节见 BP-03/BP-05）。

### 4.2 行业模板与开通模型

租户开通采用**模板装配**模式，实现"开通即有行业能力"：

```
租户注册 → 选择行业模板 → 系统装配：
   ├── 套餐与配额（设备数/用户数/AI 调用量/存储）
   ├── 行业模块插件（如"智慧楼宇模块"）
   ├── 预置业务对象与流程（如楼控空间模型、工单模板）
   ├── 预置 AI 场景包（如能耗预测；均带风险分级与默认自动化级别）
   └── 角色与权限模板（RBAC 预置）
→ 初始化站点/接入设备 → 上线运营
```

- 行业模板由平台方或生态 ISV 制作，经审核上架（走插件生命周期管理）。
- 一个租户可叠加多个行业模板（如某企业同时用"企业运营 + 智慧楼宇"）。

### 4.3 订阅与计量

| 维度 | 内容 | 计量来源 |
|---|---|---|
| 基础套餐 | 行业模块许可、功能版本 | 订阅 |
| 设备量 | 设备连接数、消息条数 | IoT 接入层 |
| 存储量 | 时序数据、录像、文件 | 数据层 |
| AI 用量 | 模型调用次数/Token（受 ADR-0002 成本因子约束） | AI 能力层 |
| API 用量 | 开放 API 调用次数 | API 网关 |

计量数据同时服务于：计费账单、五因子中"成本"裁决、租户运营分析。

## 5. 端到端业务主线（价值流）

### V1 日常运营主线（平台核心价值闭环）

```
设备/系统接入 → 数据采集（含质量评估）
   → AI Policy 闸门（五因子裁决，ADR-0002）
      ├── L1 低风险：自动联动执行（规则/模型直接闭环）
      ├── L2 中风险：AI 建议 → 人工确认 → 执行
      └── L3 高风险：仅输出洞察，人决策
   → 处置闭环（工单/警情流程 → 结果回写）
   → 运营复盘（报表/驾驶舱 → 反哺业务价值评估与模型优化）
```

### V2 租户开通主线

见 4.2：注册 → 选模板 → 装配 → 初始化站点与设备 → 上线。

### V3 生态合作主线

开发者/ISV 接入 → 开发插件或 API 应用 → 平台审核上架 → 租户订阅安装 → 用量计量与分成结算。

## 7. 开放问题（后续决策）

1. 行业模板的形态细则：模板 = 插件包 + 配置包 + AI 场景包的组合契约（待 BP-06/插件 ADR）。
2. Site 模型的行业扩展机制：行业模块如何在不改内核主数据的前提下扩展站点子类型。
3. 警备/医疗行业的处置流程与合规要求细化（与行业专家共创）。
4. 多行业叠加租户的能力边界（跨行业联动的风险等级如何取高者）。
