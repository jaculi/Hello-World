# JSL 平台 Blueprint（架构蓝图总纲）

> 状态：基线 v0.1（2026-09-05）
> 本文档是 JSL 平台架构蓝图的入口与总纲。所有架构决策须与本总纲及 [ADR](../adr/README.md) 保持一致。

## 1. 平台定位

JSL 是面向**企业运营、工业 IoT、智慧楼宇、智能农业、智能医疗、远程警备**及未来行业扩展的**多租户 AIoT 智能运营平台**。

- AI **不是**孤立业务平台，而是作为**横向智能能力**融入 Business、IoT、安全运营和各行业模块。
- 平台以 **SaaS** 形态交付，面向**长期企业运营**设计。

## 2. 核心架构原则

1. **AI 横向化**：AI 以能力服务形式横向提供，供各域按需调用；不设独立 AI 业务线。
2. **平台内核稳定、行业可插拔**：新行业通过行业模块/插件接入，内核不动。
3. **开放生态**：能力通过开放 API 对外暴露，差异通过插件扩展（详见各章）。
4. **多租户为底座**：租户隔离、数据权限、计量内建于每一层。
5. **i18n Day-1**：多语言、多时区、多币种从第一天内建，禁止后期补票。
6. **DDD 模块化**：以限界上下文划分模块，模块间仅通过契约（API/事件）交互。
7. **统一 IAM/RBAC**：人、插件、API、数据的权限统一管控。
8. **AI 治理受控**：数据 AI-Ready by Default；AI 启用与自动化级别由五因子闸门裁决（见 [ADR-0002](../adr/0002-ai-governance-and-five-factor-gate.md)）。

```
│            开放 API 网关（认证/鉴权/限流/计费/版本）             │
├──────────────────────────────────────────────────────────────┤
│  行业模块层：企业运营 │ 工业IoT │ 楼宇 │ 农业 │ 医疗 │ 警备 │ ... │

│  Business 业务域  │  IoT 设备域  │  安全运营域                   │
├──────────────────────────────────────────────────────────────┤
│  AI 横向能力层（模型/算法可插件化 + 五因子策略闸门）             │

```

## 6. 插件类型概览

| 插件类型 | 接入层 | 示例 |
|---|---|---|
| 设备协议插件 | IoT 设备域 | Modbus、MQTT、OPC-UA、私有协议驱动 |
| AI 能力插件 | AI 横向能力层 | 图像识别、预测模型、告警分析算法包 |
| 行业模块插件 | 行业模块层 | 新行业业务包 |
| 业务功能插件 | Business 域 | 业务规则、报表、工作流扩展 |

插件须运行于插件框架之上，受租户隔离、权限管控、沙箱与资源配额约束，并具备完整生命周期管理（注册/审核/上架/启停/升级）。
