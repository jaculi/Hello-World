## 1. 目的与范围

本文定义平台的运行面：

1. 部署架构运营视图：环境分层、租户放置与单元化、多区域与数据驻留；
2. 运营模型：计量计费、市场运营、租户生命周期、i18n 运营、客户支持；
3. 可靠性：正式 SLO、错误预算、容量管理、备份与灾备；
4. 运营日历：SecOps 与平台治理节奏；
5. 演进治理：Blueprint/ADR 流程与版本兼容策略。

硬约束（继承）：

- 云中立 K8s，SaaS 与专有云同一套制品（ADR-0003）；
- **数据驻留：租户数据不出其所属区域**（BP-05 §9.3）；
- 计量口径唯一来源是事件流水（BC-P3），计费与分成、五因子成本共用一套口径（ADR-0002）；
- i18n 词条覆盖率是**发布门禁**（八项基线之 i18n Day-1）。

## 2. 部署架构运营视图

### 2.1 环境分层

| 环境 | 用途 | 数据策略 |
|---|---|---|
| dev | 日常开发 | 合成数据（禁止真实 S3/S4，BP-05 §6.3） |
| staging | 发布前验证、压测、插件兼容验证 | 脱敏子集 + 合成 |
| prod（SaaS） | 生产多租户 | 真实数据，全量管控 |
| 专有云通道 | 医疗/警备 T1 客户 | 同 Chart 离线交付，客户自持或代运维 |

### 2.2 租户放置与单元化（Cell 架构）

```
全局控制面（账户/目录/路由/计量汇总）
    │ 租户 → Cell 映射（开通时决定，可迁移）
    ▼
Cell = 一个数据面部署单元（K8s 集群或集群分区）
  ├── 标准 Cell：T3 租户混部（行级隔离），共享节点池
  ├── 敏感 Cell：T2 租户（独立 schema），独立命名空间 + 网络策略
  └── 专属 Cell：T1 / 专有云（独立集群，物理隔离）
```

- 放置规则由开通套餐 + 合规要求决定（BP-03 §3.1）；BC-P1 登记映射，数据访问层按路由表分发（BP-04 §4.5）；
- **Cell 间互不可见**：平台运营方的全局报表只消费**聚合计量与运营指标**（BC-P3/BC-B3 汇总），不聚合租户明细数据——平台级分析合规问题的解法（回应 BP-03 开放问题 4）；
- Cell 容量水位监控 → 新 Cell 开辟或租户迁移（迁移 = 快照 + 双写 + 切流，离线窗口 ≤ 1h）。

### 2.3 多区域与数据驻留（回应 BP-04 开放问题 6）

- **区域 = 独立数据面**（含存储与计算），租户创建时指定 home region，其全部数据（含媒体、时序、备份）留在区内；
- 全局控制面仅持账户与路由信息，不存业务数据；
- 区域内按 §2.2 Cell 架构切分；BYOK 按区域独立 KMS（BP-05 开放问题 4 的落地基准）；
- 区域开设节奏由市场驱动（v0.1 先单一区域 + 专有云并行）。

### 2.4 发布管理

- GitOps（ArgoCD）：环境分层晋级 dev → staging → prod / 专有云；
- 节奏：内核 minor 双周；事件/API 破坏性变更走 major（N-1 兼容 ≥ 6 个月，BP-06 §3.4）；插件与行业模板独立节奏，随市场审核发布；
- 策略：金丝雀（按 Cell 灰度）→ 全量；错误预算耗尽自动冻结发布（§4.2）；回滚预案每个变更必配；
- 事件契约破坏性变更双跑过渡（BP-03 §5.2）；插件升级独立于平台发版（BP-06 §4.2）。

### 2.5 边缘运维

- 边缘节点（k3s）：远程纳管、配置下发、应用升级经云端控制通道；断网自治（本地规则续传，BP-04 §4.1）；
- 边缘监控指标与心跳回传；离线超时告警进入支持流程。

## 3. 运营模型

### 3.1 计量计费运营（BC-P3 口径定稿）

| 计量维度 | 口径 | 单位 | 账期处理 |
|---|---|---|---|
| 设备连接 | 日均活跃连接数（峰值另计，超套餐峰值单独计价） | 连接·月 | 日聚合 → 月账单 |
| 消息量 | 上行遥测消息条数（下行命令基线内免费） | 万条 | 日聚合 |
| 存储 | 时序（原始+聚合）与对象存储占用 | GB·月 | 日快照 |
| AI 用量 | 推理调用次数；LLM 按 Token | 次 / 千Token | 实时流水 |
| API 用量 | 开放 API 调用次数（按域） | 万次 | 日聚合 |

- 账期：计量日聚合 → 次月 1 日出账 → 支付期 15 天 → 逾期宽限 7 天 → **冻结写操作**（只读保留）→ 逾期 30 天启动注销流程（衔接 BP-05 §6.4 数据冻结与删除证明）；
- 升降配额即时生效（限流参数热更新）；套餐变更计费按比例折算；
- 内部成本与对客计费同口径（BP-04 §7），毛利按租户/行业/Cell 可视。

### 3.2 市场与生态运营（BP-06 参数定稿）

| 参数 | v0.1 基线 |
|---|---|
| 审核 SLA | 自动校验 ≤1 天；技术+安全评审 ≤10 个工作日；行业合规 ≤15 个工作日 |
| 分成 | 平台 : 开发者 = 20 : 80（订阅与用量同比例；运营可调） |
| 结算周期 | 月结，账期 30 天，门槛金额起付 |
| 开发者计划 | 免费沙箱租户（限量配额）；认证 ISV 加大配额与技术支持 |
| 市场指标 | 上架数、装机租户数、生态收入占比、审核通过率 |

### 3.3 租户生命周期运营

```
注册 → 试销（试用期额度）→ 付费开通（选区域/Cell/套餐/行业模板）
→ 日常运营（升降级/加购/模板叠加）→ 冻结/恢复 → 注销（冻结期 30 天 → 删除 → 删除证明）
```

- 试销转化、健康度（活跃度/用量趋势）纳入客户成功看板；
- 时序 TTL、降采样、留存参数按套餐租户化（BP-03 §6），变更走工单审计。

### 3.4 i18n 运营（八项基线落地）

- **基线语言：zh-CN + en-US（发布门禁：覆盖率 100%）**；Tier-1 扩展语言按市场确定（含 ja-JP 候选），Tier-1 语言门户覆盖率 ≥95% 可发布对应市场版本；
- 词条流程：消息码注册 → 基线翻译 → 机器翻译草稿 → 人工审校 → 发布（低风险流程，按 ADR-0002 属 L1 可自动化，审校人在回路）；
- 本地化规范：ICU（数字/日期/复数）；时区全 UTC 存储展示转换（BP-03 §4.2）；货币展示按租户币种，换算仅展示层；
- 行业词条由行业插件自带 i18n 包（BP-02 §6.1），随插件审核检查覆盖率。

### 3.5 支持与客户成功

| 工单级别 | 定义 | 首响 | 目标闭环 |
|---|---|---|---|
| P0 | 平台不可用 / 疑似数据越界 | 15 分钟 | 4 小时 |
| P1 | 核心功能受损（接入/闸门/通知） | 1 小时 | 1 个工作日 |
| P2 | 一般功能异常 | 1 个工作日 | 5 个工作日 |
| P3 | 咨询/需求 | 2 个工作日 | 排期 |

- 疑似越租户事件按安全最高级处理（BP-05 §10：自动隔离 + 证据保全 + 复盘）；
- 专有云客户支持边界（客户自持 vs 代运维）在合同层定义，代运维复用本 BP 全套流程。

## 4. SLO 与可靠性

### 4.1 正式 SLO（v1.0，取代 BP-04 §5 基线值）

| 指标 | 目标 | 测量点 |
|---|---|---|
| 门户/控制面可用性（月） | 99.9% | 网关探活 |
| 开放 API 可用性（月） | 99.9% | 网关 |
| IoT 接入可用性（月） | 99.9% | 接入集群 |
| 闸门裁决延迟 P99 | ≤ 50 ms | BC-A2 |
| 遥测端到端延迟 P95（上报→可查） | ≤ 2 s | I3 管道 |
| 告警产生→通知投递 P95 | ≤ 30 s | I4→P4 |
| 开放 API 延迟 P99 | ≤ 500 ms | 网关 |
| 事务数据 RPO | ≤ 5 min | 备份体系 |
| 区域级故障 RTO | ≤ 1 h | 灾备演练实测 |

### 4.2 错误预算与发布门禁

- 每个 SLO 对应月度错误预算；预算剩余 <25% 警告（变更审批升级），耗尽冻结该域发布（仅允许可靠性修复）；
- SLO 违约触发复盘（无责事后复盘，输出 ADR/流程改进）。

### 4.3 容量管理

- 三指标驱动（BP-04 §7）：设备连接数、消息速率、AI 调用峰值；每季度压测校准容量模型；
- 扩缩容：无状态服务 HPA；Cell 水位 >70% 触发扩容/新 Cell；GPU 池按 AI 用量趋势预扩（提前期长）；
- 成本联动：容量决策必须附成本预测（FinOps 评审）。

### 4.4 备份与灾备

| 对象 | 策略 |
|---|---|
| PostgreSQL | 跨 AZ 流复制 + PITR，全备日备 |
| 事件日志（Kafka） | 副本跨 AZ；回放窗口 ≥30 天（BP-03 §2.2） |
| 对象存储 | 跨 AZ + 版本化；关键证据类 WORM（BP-05 §9.2） |
| 时序库 | 快照 + 冷数据 Parquet 可重建（BP-03 §6） |
| 专有云 | 备份策略随交付合同定义（客户自持/代运维），最小基线同上 |

- 灾备演练：区域级切换演练每半年一次（RTO 实测校准）；备份恢复抽查每月一次。

## 5. 运营日历（SecOps 与治理节奏）

| 节奏 | 事项 |
|---|---|
| 每周 | 安全告警周报、越界对账结果复核（BP-03 §3.2） |
| 每月 | 备份恢复抽查、密钥与证书轮换检查（BP-05 §10）、账期对账、SLO 报告 |
| 每季度 | 压测与容量评审、FinOps 成本评审、错误预算复盘、依赖/镜像漏洞全面扫描 |
| 每半年 | 灾备演练、渗透测试（BP-05 §10）、权限与 RBAC 审计（最小权限校准） |
| 每年 | 第三方安全审计/合规认证复审（等保等）、架构评审大会（Blueprint 全量修订） |
| 事件驱动 | P0 事故复盘、破坏性变更评审（major 发布前） |

## 6. 可观测运营

- 平台运营方驾驶舱（BC-B3）：全局 SLO 达成、Cell 水位、计量收入水位、生态指标（§3.2）、安全态势；
- 告警分级对接支持工单（§3.5），P0 自动升级值班链；
- 审计流独立于业务观测管道（防篡改），访问最小化（BP-05 §9）。

## 7. 演进治理（长期企业运营的落实）

- **文档即架构**：BP 随 ADR 更新（如 ADR-0003 落地后 BP-04 引用同步）；Blueprint 每年全量修订一次，平时增量；
- **决策流程**：跨模块结构/选型/原则变更 → 必须立 ADR（八项基线之五）；ADR 索引为唯一权威记录；
- **兼容性责任**：内核 API/事件/插件 SPI 按 N-1 策略；`kernelCompatibility` 区间管理插件兼容（BP-06 §4.1）；
- **技术债**：各 BP §开放问题汇总进技术债看板，季度评审排期（本套 v0.1 共约 20 项，多数已指定归属 ADR/文档）；
- **行业扩展路线**：新行业立项 → 行业模块插件 + 行业模板 + 行业合规评审 → 沙箱租户试点 → 市场上架；内核不改动为验收标准（ADR-0001 验证点）。

## 8. 开放问题（后续决策）

1. 首个生产区域与云厂商合约（云中立基线下的具体落地）——商业决策 + ADR 记录差异。
2. 专有云代运维服务的产品化范围与定价——商业化立项时定。
3. 计费系统自研 vs 集成第三方（Stripe/国内支付+发票体系）——首个付费租户前立 ADR。
4. 试销期默认额度与转化策略基线——市场冷启动阶段定。
5. 多区域开设的触发标准（合规需求/客户规模阈值）——随首单跨区客户评估。
