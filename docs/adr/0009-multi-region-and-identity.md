# ADR-0009：多区域数据驻留与跨区身份

- 状态：**Accepted**
- 日期：2026-09-05
- 关联：[ADR-0003](./0003-technology-stack-baseline.md)、[BP-05 §6.1/§9.3](../blueprint/05-security-architecture.md)、[BP-07 §2.2/§2.3/§9](../blueprint/07-deployment-and-operations.md)

## 背景（Context）

BP-07 §2.3 已定"区域 = 独立数据面，租户数据不出 home region"。本 ADR 正式化多区域架构模式，并补齐 BP-05 开放问题 4（BYOK 与跨区域密钥）与跨区身份模型。实施时机仍为首个跨区客户，但模式现在锁定，避免首个区域建成后返工。

## 决策（Decision）

### 1. 区域模型（正式化 BP-07 §2.3）

- **区域 = 完整数据面**：计算、存储、时序、对象、备份全部区域内闭环（RPO/RTO 在区域内度量）；
- **全局控制面只持账户、路由、聚合计量**（BP-07 §2.2 Cell 原则的区域级放大），不存任何业务数据；
- 区域内沿用 Cell 架构（标准/敏感/专属 Cell）；租户开通时绑定 home region，跨区迁移按 BP-07 §2.2 租户迁移流程（快照+双写+切流，目标区重建）。

### 2. 跨区身份：区域独立 Keycloak + 全局联合登录

- 每区域部署独立 Keycloak（资源 realm：该区域全部租户的角色/授权）；
- 全局门户经 **OIDC identity brokering 联合**到各区域 realm 登录；账户目录按区域分布，**不建全局账户明文库**（规避单点与数据驻留风险）；
- 平台运营方员工的全局运维身份单独管理（独立 realm + 高权限管控 + step-up，BP-05 §3）；
- Token 携带 `region` 声明，跨区请求一律拒绝（网关校验），不存在"跨区令牌"。

### 3. BYOK 与密钥体系（BP-05 开放问题 4 闭环）

- 每区域独立 KMS 根密钥；信封加密的租户级数据密钥（DEK）只在区域内生成与使用；
- **区域密钥不跨区备份**；区域灾备恢复依赖区域内密钥副本（区域内部多 AZ，不跨区）；
- 专有云（T1）客户 BYOK：客户根密钥由客户 KMS 托管，平台侧仅持有区域 DEK，注销流程含密钥销毁证明（BP-05 §6.4）。

### 4. 全局能力的一致性处理

| 能力 | 处理 |
|---|---|
| 计量与账单 | 区域内计量 → 聚合值上报全局控制面 → 全局出账（明细不出区） |
| 市场与插件 | 制品全局分发（签名制品可跨区），但安装实例与运行数据在区域内 |
| 审计 | 区域内完整留存（BP-05 §9）；全局侧仅审计元数据汇总 |
| 平台运营报表 | 仅消费聚合指标（BP-07 §2.2 原则） |

### 5. 实施节奏

首个区域（含专有云通道）按本模式建设；新区域开设按 BP-07 §8 开放问题 5 的触发标准评估；区域开通 SOP（建区域 = Helm Chart 部署 + KMS 初始化 + realm 联合注册 + 纳管接入）随首个跨区客户落地时文档化。

## 重审触发条件

- 出现"同一租户跨区数据合法共享"的强需求（如跨国集团同一租户）→ 评估租户级多 home 模型（新 ADR，不默认支持）；
- 全局联合登录延迟/可用性不可接受 → 评估区域登录直连模式。

## 后果（Consequences）

**正面**：数据驻留合规从架构上成立（不靠流程承诺）；区域故障爆炸半径清晰；账户数据无全局单点；BYOK 边界干净。
**负面/约束**：区域间无共享数据面，跨国租户体验受限（用户须选区域）；控制面与 N 区域的一致性维护（区域开通 SOP 复杂度）；全局出账依赖跨区聚合管道的可靠性。
