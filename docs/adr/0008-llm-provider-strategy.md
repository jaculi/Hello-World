# ADR-0008：LLM 供应商策略——混合路由与数据边界

- 状态：**Accepted**
- 日期：2026-09-05
- 关联：[ADR-0002](./0002-ai-governance-and-five-factor-gate.md)、[ADR-0003](./0003-technology-stack-baseline.md)、[BP-04 §4.3](../blueprint/04-technology-architecture.md)、[BP-05 §8](../blueprint/05-security-architecture.md)

## 背景（Context）

BP-04 §4.3 已定 LLM 网关（多供应商路由、Token 计量、注入防护、脱敏前置），首个 LLM 场景上线前需定供应商组合与数据边界规则。核心张力：外部 API 供应商模型能力强、成本低（无需 GPU），但租户数据出域；自托管 vLLM 池数据不出域，但 GPU 成本高。

## 决策（Decision）

**混合路由，按数据敏感度分流，LLM 网关统一收口（闸门之下）。**

### 1. 路由规则（数据边界优先）

| 场景数据等级 | 供应商 | 理由 |
|---|---|---|
| 含 S3/S4 数据、医疗/警备租户、租户声明数据不出域 | **自托管 vLLM 池**（开源模型） | 数据不出租户隔离单元（BP-05 §8：租户数据默认不进公共模型） |
| 非敏感通用场景（翻译草稿、公开文档摘要、报表叙述等） | 外部 API 允许 | 成本与能力优；强制脱敏前置 + 合同约束 |
| 租户自带模型（BYOM） | 经 AI Capability SPI 接入 | BP-06 §4.3，权限天花板照常约束 |

### 2. 外部 API 使用的三条硬约束

1. **脱敏前置**：出域前经脱敏管道（BP-05 §6.3），S4 字段禁止出域；
2. **合同约束**：供应商条款须含"不用客户数据训练"，逐供应商登记（合规台账）；
3. **区域一致**：外部 API 节点须与租户 home region 同区域可用（数据驻留，BP-07 §2.3），无同区能力即该区域不可用此供应商。

### 3. LLM 网关职责（BC-A1 内组件）

- 路由表：`场景 → 供应商/模型` 按租户可配（租户可整体锁定"仅自托管"）；
- 计量：Token/调用实时入 BC-P3（五因子成本因子数据源）；
- 防护：Prompt 注入防护挂点、输出过滤（BP-05 §8）、P95 延迟与错误率监控；
- 降级链：外部 API 故障 → 自托管池兜底 → 场景标记降级（均审计留痕）。

### 4. 模型清单为运营参数

不锁定具体模型厂商与版本；开源模型选型按季度评审（效果/成本/许可），模型版本化管理与回滚由 BC-A1 资产管理承担（ADR-0002）。

## 重审触发条件

- FinOps 季度评审（BP-07 §5）显示自托管池利用率 <30% 且外部 API 成本占比更高 → 缩减自托管池；
- 监管变化（如生成式 AI 合规要求收紧）→ 收紧外部 API 白名单。

## 后果（Consequences）

**正面**：敏感行业（医疗/警备）的 LLM 场景从第一天可用且合规；通用场景获得外部模型能力红利；供应商与模型完全可插拔，无锁定。
**负面/约束**：两套运行形态（vLLM 池 + 外部 API）的运维与监控双轨；脱敏前置管道的质量决定外部 API 可用边界（漏脱敏即事故，需专项测试）；GPU 池容量规划依赖 AI 用量趋势（BP-07 §4.3）。
