# ADR-0007：边缘框架基线——k3s + MQTT 桥接

- 状态：**Accepted**
- 日期：2026-09-05
- 关联：[ADR-0003](./0003-technology-stack-baseline.md)、[BP-04 §4.1/§9](../blueprint/04-technology-architecture.md)、[BP-07 §2.5](../blueprint/07-deployment-and-operations.md)

## 背景（Context）

工业、农业、楼宇等行业存在弱网/断网现场，需要边缘自治（本地规则、断网续传）与云端协同。BP-04 §4.1 已定"边缘 k3s 轻量基跑协议适配与本地规则，云边经 MQTT 桥接"，本 ADR 正式化基线并定 KubeEdge/OpenYurt 的重估条件。

## 决策（Decision）

**基线：k3s + MQTT 桥接，不引入云边编排框架。**

### 1. 边缘节点形态

- 单机 k3s（K8s 兼容 API，资源占用小，云中立无锁定）；
- 边缘负载：协议适配（W 级 WASM 协议插件，ADR-0003/0004 沙箱策略复用）、本地规则引擎子集、本地缓存与断网续传队列（本地持久化，恢复后按序上送）；
- 边缘不运行业务 BC、不落租户业务库——边缘只是"接入延伸"，数据权威在云端（BP-03 归属链）。

### 2. 云边协同

- **数据面**：MQTT 桥接（边缘 broker ↔ 云端 EMQX 类集群），遥测/事件上行、命令下行；
- **管控面**：云端边缘纳管服务负责配置下发、插件分发（签名制品，BP-05 §7.1）、OTA 升级（按站点灰度分批，失败自动回滚）、心跳与离线告警（BP-07 §2.5）；
- 升级通道与数据通道分离；边缘凭证一机一密（BP-05 §3.1），吊销即失联。

### 3. 明确不做（反范围）

- 不做边缘元数据自治同步（设备影子边缘决策）；
- 不做大规模边缘节点统一编排面；
- 不在边缘存 S3/S4 级数据的持久副本（BP-05 §6.1；摄像头等本地证据属设备侧存储，接入逻辑按行业模块处理）。

### 重估条件（满足任一，评估 KubeEdge/OpenYurt）

- 边缘节点规模 > 500，且需要统一的节点生命周期编排；
- 出现"边缘自治决策"类需求（断网期间需本地影子/规则长期闭环）——先评估"增强本地规则子集"能否覆盖，不能覆盖再引入框架；
- 客户明确要求纳入其既有 KubeEdge/OpenYurt 体系。

## 后果（Consequences）

**正面**：边缘侧复杂度最小化，与主栈（K8s API、WASM 插件、MQTT）完全同构；升级与安全模型复用平台既有机制；无框架锁定。
**负面/约束**：站点数量大时纳管服务需自建分批与幂等（框架本可提供）；断网自治能力边界受"本地规则子集"限制，需求膨胀时需按重估条件升级。
